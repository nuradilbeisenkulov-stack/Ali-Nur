# Получателю проекта

1. Распакуйте ZIP. Внутри находится папка `support-copilot`.
2. Откройте эту папку в VS Code. В корне видны README.md, Dockerfile, app, scripts, tests.
3. Для запуска на своём компьютере с Docker выполните `docker compose up --build` и откройте http://localhost:8000 . Первый запуск работает без ключа и без частных файлов.
4. Для Gemini скопируйте .env.example в .env, добавьте свой ключ и перезапустите по README.

## Загрузить на GitHub

Рекомендуемый способ — через GitHub Desktop: File → Add Local Repository, выберите папку `support-copilot`. Если программа сообщает, что это ещё не репозиторий, выберите создание репозитория в этой папке. Сделайте первый commit и нажмите Publish repository. Учётная запись и выбор доступности принадлежат получателю.

Или через терминал в этой папке (нужен установленный Git и вход в GitHub):

```sh
git init
git add .
git status
git commit -m "Add Support Copilot MVP"
git branch -M main
```

На GitHub создайте пустой репозиторий без автоматически созданного README. Скопируйте его URL и выполните, заменив OWNER и REPOSITORY:

```sh
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Загружайте распакованные исходники, а не один ZIP. В Git должны попасть скрытые `.gitignore`, `.env.example`, `.dockerignore` и `.github/workflows/checks.yml`. Файл `.env`, локальные базы и папки `work`, `private_data`, `data` исключены. Не меняйте это исключение, чтобы добавить ключ.

После push вкладка Actions запускает тесты и сборку Docker; интернет для установки зависимостей нужен. Сам сайт на GitHub от загрузки исходников не появляется. Другой разработчик сможет клонировать репозиторий и запустить его командами README.

Официальные данные кейса не входят в архив. Встроенный demo_data — отдельная демонстрационная конфигурация без официальных пунктов правил. Для полного кейса получатель подключает свои разрешённые файлы приватно.
